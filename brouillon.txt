Système de Gestion des Congés (SIRH)

Le contexte : 
    Une application interne d'entreprise permettant aux employés de poser leurs congés
    payés, leurs RTT, et de déclarer leurs heures supplémentaires.

La complexité métier attendue :
    ● Le calcul des jours réels : lorsqu'un employé pose des congés du 20 au 28 du mois, le
    système doit déduire uniquement les jours ouvrés, en ignorant les week-ends et les jours
    fériés officiels.
    ● L'anticipation stricte : il est interdit de poser une demi-journée de congé pour le jour même,
    sauf s'il s'agit d'un motif "Urgence Familiale" (qui puise dans un quota spécial).
    ● Le flux d'approbation des heures supplémentaires : les heures déclarées au-delà du forfait
    hebdomadaire peuvent être soit payées, soit transformées en récupération, selon le choix
    de l'employé, mais uniquement après validation du manager direct.



API : 
    POST /congés 
        - INPUT : deux dates (+ raison?)
        - OUTPUT : OK + type ? nombre de j posé ? || PAS OK + raison 
    
    GET /congés?ID | ?jour
        - INPUT ID
        - OUTPUT Listes congés ?pour une personne ou un jour

    POST /heuresSupp
        - INPUT Date + heures
        - OUTPUT : OK + nb d'heures supp || PAS OK + raison 
    GET /heuresSupp?ID | ?jour
    



BDD :
    Congés
        ID 
        date debut         
        date fin
        jours décomptés
        type

    HeuresSupp
